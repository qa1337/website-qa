Test design techniques

You can't test every possible input. These techniques help you choose a small set of tests that still finds most of the bugs.

Equivalence partitioning

Split the possible inputs into groups that the app should treat the same way. Test one value from each group. If one value in a group works, the others most likely do too. 

Requirement: shipping is free for orders of $50 or more.

Partition               Example   Expected
Invalid: below $0       -10       Error
Valid: $0 to $49.99     30        Shipping charged
Valid: $50 and up       80        Free shipping
Invalid: not a number   abc       Error
  • Always include the invalid groups, not just the valid ones.
  • Partitions also apply to things other than numbers: user types, file types, countries, payment methods.

Boundary value analysis

Bugs gather at the edges, where a developer wrote > instead of >=. For each boundary, test the value just below, on and just above it. 

Requirement: a password must be 8 to 64 characters.

Length   Expected
7        Rejected
8        Accepted
9        Accepted
63       Accepted
64       Accepted
65       Rejected

Boundaries are everywhere

  • Character limits in text fields and usernames.
  • File size and image dimension limits.
  • Dates: end of month, leap years, midnight, daylight saving changes.
  • Lists: zero items, one item, the page size, one more than the page size.
  • Money: $0.00, $0.01, the maximum transaction amount.
Use them togetherPartition first to find the groups, then test the boundaries between them. With the shipping example: 49.99, 50.00 and 50.01.

Exploratory testing

Learning, designing and running tests at the same time, without a script. You follow what the app shows you and dig where something feels off. It finds bugs that scripted tests miss.

Run a session

  1. Write a short charter: what you will explore and what you are looking for.
  2. Set a time box, for example 45 to 60 minutes.
  3. Explore. Take notes of what you tried, questions and anything strange.
  4. Write up bugs and follow-up ideas at the end.
Charter: Explore the checkout with saved cards
to find problems with expired and removed cards.

Time box: 45 min
Device:   iPhone 15, iOS 18
Notes:    ...
Bugs:     ...
Ideas:    try the same on Android, try with a card removed on web

Ideas to try

  • Interrupt: incoming call, notification, rotate the screen, lock the phone.
  • Go back and forward in an unusual order.
  • Use two devices or two tabs with the same account.
  • Change settings mid-flow: language, dark mode, text size, permissions.
  • Think like a specific user: new, impatient, on a bad connection.
Exploratory is not randomIt has a goal, a time limit and notes. Without them it is hard to say what was tested.

Other techniques worth knowing

  • Decision tables: list every combination of conditions and the expected result. Useful for business rules with several inputs.
  • State transition testing: map the states an item can be in, like an order going from placed to paid to shipped, and test every allowed and forbidden move.
  • Error guessing: use experience to target what usually breaks: empty values, special characters, slow networks, double taps.
