Functional and non-functional testing

Functional testing checks what the app does. Non-functional testing checks how well it does it: how fast, how easy, how accessible and how safe.

Functional testing

Every feature behaves as the requirements say. You compare the actual result with the expected one.

  • Sign in, sign up, password reset.
  • Forms validate input and show clear errors.
  • Calculations are correct: totals, taxes, discounts.
  • Permissions: users only see and change what they are allowed to.
  • Notifications, emails and deep links open the right place.
Expected result firstWrite down what should happen before you run the test. Otherwise it is easy to accept whatever the app does.

Performance testing

How the app behaves under time and load pressure.

  • Load: expected number of users at the same time.
  • Stress: more than expected, until something breaks. How does it fail?
  • Soak: normal load for hours, to find memory leaks and slow decay.
  • Client side: launch time, screen load time, scroll smoothness, battery use.

Quick checks you can do without tools

  • Test on an old, low-end device, not only the newest phone.
  • Throttle the network to slow 3G in DevTools or with the emulator settings.
  • Load a list with hundreds of items, not just three.
  • Leave the app open in the background and come back later.

Usability testing

Can people use it without help?

  • Can a new user finish the main task without instructions?
  • Are labels, errors and empty states clear?
  • Is the flow consistent with the platform: back button, gestures, keyboard types?
  • Are buttons big enough to tap, and easy to reach on a large phone?

Accessibility testing

Everyone can use the app, including people who use screen readers, larger text, keyboard only or high contrast.

  • Turn on VoiceOver (iOS) or TalkBack (Android) and complete the main flow.
  • On web, use only the keyboard: Tab, Shift+Tab, Enter, Space, Esc.
  • Set the largest text size and check nothing is cut off.
  • Every image and icon button has a meaningful label.
  • Color contrast meets WCAG AA, and color is never the only signal.

See the accessibility pass in Checklists.

Security testing

Data stays private and users can't do more than they should. Deep security testing is a specialist job, but QA can catch the common problems.

  • Change an ID in a URL or request. Can you see another user's data?
  • Sign out, then press back. Is private data still on screen?
  • Are passwords, tokens or personal data written to logs or local storage?
  • Do sessions expire, and does a changed password sign out other devices?
  • Is every request sent over HTTPS?
Only test what you ownRun security checks on your own app and test environments, with permission. Never against systems you don't have approval to test.

Other non-functional types

  • Compatibility: devices, OS versions, browsers. See Device fragmentation.
  • Reliability: airplane mode, lost connection, app killed mid-action.
  • Localization: long translations, right-to-left languages, date and number formats.
  • Install and update: fresh install, update from the previous version, data kept after update.
